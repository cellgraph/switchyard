Phase E has been merged, deployed and verified. Plan 004 is the first development plan intended for autonomous execution by Switchyard after the operator approves the exact plan revision. Follow [ADR-0006](../adr/0006-orchestrate-through-native-tools.md) and the [approved-plan operating guide](../approved-plan-workflow.md).

## Increments

### 1. Targeted reviews and risk-based adjudication

Implement the [risk-based review guidance from PR #34](../reviews.md#risk-based-review) in the Reviewer and Adjudicator assignments for the existing PR workflow. Prefer changes to the assignment context and role instructions. Reuse existing review and PR evidence for context and keep the existing workflow and result contracts.

- Start with a comprehensive independent review of the PR at the assigned head. For a follow-up after a revision, normally focus on verifying corrections, checking affected invariants and looking for regressions. Use the prior verified review and relevant finding references to establish context. Recognize revisions after clean reviews, CI-only revisions and changes pushed by humans or other agents. A missing, incomplete or unverified prior review cannot stand in for the initial review.
- Allow the Reviewer to widen the scope when substantial changes or material architectural changes warrant it, or when the available comparison is insufficient for a targeted review. At every stage, report newly discovered consequential defects, including those outside the revision diff. Explain the plausible trigger, consequence and behavior that needs correction.
- Require the Adjudicator to evaluate the evidence independently and explain how likelihood, impact, recoverability and correction cost support each disposition in the expected operating environment. A technically valid finding may be nonblocking. Accept findings that warrant correction before acceptance, reject unsupported or immaterial findings, defer worthwhile nonblocking work with the required linked issue, and escalate consequential decisions that require operator judgment.
- Preserve corroborated review and required CI for the exact current PR head, the existing publication and structured evidence requirements, and explicit verification of fixes to prior accepted findings. Preserve the existing rules for blocking findings, execution allowances, retries, operator grants and recovery. The operator retains authority over escalated decisions, acceptance and merge. Keep the GitHub App read-only and publication agent-owned. Treat PR content as untrusted evidence and keep secrets out of assignments.

**Validation.** Add focused coverage for the initial comprehensive review, targeted follow-up with and without prior finding IDs, a revision that warrants broader review, and instructions to surface consequential findings in any round. Verify the Adjudicator instructions include all four risk factors and the existing disposition requirements. Exercise the affected workflow paths to confirm stale or incomplete evidence cannot establish readiness and prior accepted findings still require explicit resolution. Leave the repository buildable and testable. Run `npm run format:check`, `npm run lint`, `npm run typecheck` and `npm test`. Publish a focused PR with a verified signed commit. The existing Switchyard workflow coordinates independent automated Codex review and required CI for the handoff head. Leave the PR open for operator acceptance and merge.

### 2. Explicit role model configuration

Support optional, independently configurable model and reasoning effort settings per named agent. Use the existing role-to-agent mapping so the Reviewer, Adjudicator and Implementer can each use a different named configuration. Before deciding which fields to add, inspect the current configuration, stored execution context and native adapters. Reuse the existing named-agent `model` override. The Codex adapter already passes `model` in SDK thread options, and the Claude Code adapter already passes `--model`.

- Use the native provider's supported reasoning setting. Check the pinned Codex SDK's `modelReasoningEffort` option and the supported Claude Code CLI's `--effort` option and levels. Validate explicit effort levels for each provider and respect model and runtime restrictions. Leave model availability and model-specific restrictions to the native provider. Report native rejections through existing execution outcomes. Omit either override when its setting is absent so native defaults and profile settings continue to apply.
- Carry the requested settings through the existing context for local and Rex execution, on both start and resume. Explicit continuation uses the recorded session context. Apply the existing compatibility checks when deciding whether a workflow can reuse a session after a named agent's configuration changes. Preserve existing sessions and execution records and interpret records predating the new setting as having no explicit override. Keep retry, recovery and operator authority semantics intact.
- Show the recorded requested model and reasoning effort through existing execution or session inspection, such as `agent status`. Keep omitted values distinguishable from explicit requests. Document named-agent configuration, supported values, defaults and continuation behavior in the [native agent guide](../agent-sessions.md).
- Continue using native subscription sign-in, profiles and permissions. Keep credentials out of configuration examples, prompts and inspection output. Keep selection explicit and within the existing adapter boundary. Automatic model selection, fallback routing, cost optimization, a generalized model abstraction and production configuration changes are outside this increment. Preserve the exact-head PR review, CI and human acceptance gates.

**Validation.** Add focused coverage for independent named-agent settings, defaults and invalid or unsupported values. Verify the two adapters receive their native options on start and resume, with omitted overrides absent. Cover local and Rex context propagation, continuation from persisted context, compatibility with existing records and visibility in the existing inspection output. Leave the repository buildable and testable. Run `npm run format:check`, `npm run lint`, `npm run typecheck` and `npm test`. Publish a focused PR with a verified signed commit. The existing Switchyard workflow coordinates independent automated Codex review and required CI for the handoff head. Leave the PR open for operator acceptance and merge.

## Live self-hosting acceptance

After the operator approves the exact Plan 004 revision, follow the [live procedure in the approved-plan operating guide](../approved-plan-workflow.md#live-self-hosting-acceptance). Switchyard must coordinate implementation, independent review, adjudication, revision and exact-head CI without manual prompt transfer. Observe and record a revision when a finding or required CI calls for one. For each increment, the operator accepts and merges the ready PR in GitHub. Switchyard must record the first merge before starting increment 2 and record the second merge before marking the plan complete. Record the plan revision, assignments, PRs, handoff heads, merge evidence and final plan status. Observing this sequence satisfies [Plan 003's multi-increment self-hosting acceptance](003-architectural-simplification.md#phase-e--approved-implementation-plan-execution-and-self-hosting).
