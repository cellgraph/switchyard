# Claude Code authentication follow-up

- Status: Proposed for operator review before Phase 5.6C
- Date: 2026-11-24
- Baseline: Switchyard `fb0e0d0` (Phase 5.6B)

## Investigation

**Current adapter.** Both local and distributed execution use the same worker factory. It requires `ANTHROPIC_API_KEY`, passes it through an explicit `apiKeyHelper`, and expects that source in Claude's initialization frame. The launcher also uses `--bare`, restricted and safe modes, explicit tools and permissions, and an unmanaged profile. Anthropic excludes helper-provided keys from server-managed settings delivery. The shipped setup remains in the [Claude operating guide](../claude-code.md). [Server-managed settings](https://code.claude.com/docs/en/server-managed-settings#platform-availability)

**Documented native behavior.** Claude's `--print` mode can use a stored subscription login. The pinned CLI's help confirms that `--bare` skips OAuth and Keychain reads. Anthropic documents separate sign-in and transcript storage by `CLAUDE_CONFIG_DIR`. On macOS, Claude uses a profile-specific Keychain entry and can fall back to a mode-0600 profile file if the Keychain is unavailable for writes. The native runtime owns refresh and can require a new browser sign-in. Non-bare print mode can load project hooks and MCP servers without an interactive trust prompt. The operator must trust the repository and effective native configuration, or use native controls to limit what it loads. [Headless execution](https://code.claude.com/docs/en/headless) · [Authentication](https://code.claude.com/docs/en/authentication#credential-management) · [Permissions](https://code.claude.com/docs/en/permissions)

**Observed on the arm64 Mac mini.** The installed CLI was 2.1.331. The temporary 2.1.330 binary matched Anthropic's published SHA-256 and passed the macOS signature check for Anthropic PBC. A fresh profile reproduced Switchyard's preflight rejection before CLI launch. The root-owned system file `/Library/Application Support/ClaudeCode/managed-settings.json` contained only `sandbox.enabled: false`. The guard checks for the file's presence. The native probes left the policy in effect. The installed 2.1.331 also fails Switchyard's separate version check. [Managed settings](https://code.claude.com/docs/en/managed-settings) · [Binary verification](https://code.claude.com/docs/en/setup#binary-integrity-and-code-signing)

- Fresh-profile `auth status --json` returned signed out and `apiProvider: "firstParty"` in both versions. Scratch headless runs used the existing stream and permission flags with the key helper removed. With and without `--bare`, init reported `apiKeySource: "none"`, `dontAsk`, and empty MCP and additional directories. Bare exposed `Read`. Omitting bare with the same requested list exposed `Glob`, `Grep`, and `Read`. Both exited 1 with a login error and emitted a terminal frame with `is_error: true` and subtype `success`.
- On 2.1.330 without bare, explicitly requesting `Read`, `Read,Edit`, or `Read,Edit,Write` produced the requested tools. `StructuredOutput` appeared when requested by schema. With the remaining restrictions in place, scratch hooks and project MCP left no startup marker, and init still listed native built-in plugins. This proves startup behavior for those flag combinations. Native execution with the operator's actual profile remains untested.
- Both Phase 5.6B Codex worker profiles reported ChatGPT login with the bundled 0.171.0 CLI in the worker's allowlisted environment. Completed and interrupted rollouts in both profiles carried `plan_type: "plus"`. That supports subscription use for the recorded turns. The worker selects the SDK API-key route if its launch environment supplies `OPENAI_API_KEY`. [Codex sign-in](https://github.com/openai/codex#using-codex-with-your-chatgpt-plan) · [Distributed smoke record](../distributed-workers.md#credentialed-execution-record)

The fresh Claude profile is signed out. Successful subscription inference, effective native settings in the worker context, refresh across restarts, and the pinned CLI's exact quota error shapes remain unverified. The spike used no Anthropic API key and made no billed Claude request.

## Proposed launcher and responsibilities

[ADR-0005](../adr/0005-trusted-execution-environments.md) defines the trust and execution boundary. Use one native Claude launch for both authentication modes. Reuse the existing worker factory, process runner, stream parser, worktree checks and session checkpoints.

The existing Claude adapter has no deployed consumers, production configurations or authenticated sessions. Replace its launcher, config shape, runtime fingerprint, tests and setup instructions directly. The upgrade can require the new Claude config and a fresh Claude session. It needs no compatibility reader, session migration or parallel launcher. Keep the existing Codex configuration and session behavior and preserve the controller database and durable workflow data.

Keep `--print`, stream JSON and model/session selection, and request a schema when the workflow requires one. Verify the initialization and terminal evidence, exit, checkout and exact transcript path and identity. Keep process-group cancellation and the existing hold on uncertainty. If native background work interferes with terminal evidence or survives the managed process group, use the narrow native lifecycle control that addresses the observed problem, or require the operator to disable that feature for the worker. Cancellation cannot recall actions already taken, stop independent processes outside the group, or cancel remote jobs.

Review prompts can reuse the existing worker input. A changed or unverifiable checkout invalidates the result and holds the turn for inspection. Keep the before/after checkpoint, exact-head and identity checks and controller terminal validation. A remote turn result leaves the independent review and CI gates in place. Remove the fixed `sandbox: "read-only"` field from worker registration and status. Coordinate the controller and worker upgrade after outstanding turns finish or are held through existing recovery. Keep the existing database. Workers refresh their registration through the existing poll loop. Add transitional field handling only if a deployed consumer actually depends on it. Match workers on the existing repository, provider and model fields. Keep worker identity, lease, incarnation, fencing and affinity. Checkout verification and controller publication gates cover their own evidence and actions. Agents can still use any independent host permissions, including credentials that allow network writes or publication.

For Codex, keep the working SDK profile, sandbox options and shell environment controls. The SDK already offers these settings natively, and there is no current blocker from those defaults. The pin, indexed rollout lookup and refusal of a conflicting managed SQLite location protect session continuity. Documentation can clarify the API-key environment override and its consequence for subscription use. Codex changes can wait for a concrete operator or recovery need.

## Authentication and billing

- Require `claude.authMode` to be explicitly set to `subscription` or `api-key` on the execution host. Reject missing or unsupported values. For subscription, the operator runs `claude auth login --claudeai` using the same canonical `CLAUDE_CONFIG_DIR` and OS account as the worker. Let Claude store and renew the login. Keep the profile dedicated to this account. Check native `auth status --json` with the launch environment before each turn and require the expected profile and first-party `claude.ai` login on a supported personal paid plan. Use `apiKeySource` as corroborating evidence once verified on the pinned version. `none` also occurs on signed-out runs.
- Keep subscription launches free of API keys, helpers, endpoint or provider overrides and other externally supplied auth inputs. The operator must configure the profile and effective native settings with a single subscription credential source, including when it expires. A status check describes the active credential. It cannot prove what other sources could take over later. Refuse an ambiguous or mismatched auth result. Leave subscription mode disabled if the single-source prerequisite cannot be met with native configuration. Switchyard never retries a subscription turn using API credentials. [Credential precedence and expiration](https://code.claude.com/docs/en/authentication#authentication-precedence) · [CLI authentication status](https://code.claude.com/docs/en/cli-reference#cli-commands)
- Disable Claude Usage credits before any credentialed subscription run. This is an operator-managed prerequisite because the available stream signals do not establish the setting before inference. A subscription login can incur separately billed overage under the same credential. Keep the work scoped to the operator's own account and unmodified native CLI. Anthropic restricts offering its subscription login or routing user requests through subscriptions in third-party products. [Usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans) · [Usage policy](https://code.claude.com/docs/en/legal-and-compliance#usage-policy)
- For API-key mode, require the operator-provided `ANTHROPIC_API_KEY` on the execution host and give it to the native CLI through its documented environment variable. Use the same non-bare launch and native auth status check, with API-key evidence and the optional CLI budget. Remove the old helper, restricted launcher and managed-settings guard. Bind the native profile, explicit mode, executable and version to the runtime identity without hashing credentials. Hold changed bindings for inspection. Keep token usage. Report authentication failure and distinguish subscription limits, provider throttling and API budget exhaustion where the stream provides reliable evidence. Omit subscription USD estimates from spend evidence. Neither a generic `429` nor a CLI cost estimate establishes a billing route. [Native API-key authentication](https://code.claude.com/docs/en/authentication#authentication-precedence) · [Rate-limit events](https://code.claude.com/docs/en/agent-sdk/typescript#sdkratelimitevent) · [API errors](https://platform.claude.com/docs/en/api/errors) · [Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

## Bounded implementation and validation

1. **Native gate.** After operator sign-in and confirmation that Usage credits are off, run one harmless prompt from a trusted scratch checkout on the Mac mini as the worker user. Use pinned 2.1.330, the dedicated profile, explicit model and `--print --output-format stream-json --verbose`. Confirm first-party subscription status, initialization, terminal success, clean checkout and the expected transcript. Use a bare negative control only if needed. Verify the interactive profile remains separate and the worker process can access the native login after restart.
2. **Adapter and automated coverage.** Replace the obsolete launcher tests and setup instructions with shared native-launch coverage for both explicit modes. Reuse the fake CLI and loopback harnesses. Cover missing mode, auth mismatch, missing or contradictory result evidence, review changes including ignored content, bounded fix candidate rejection, mode/profile mismatch on resume, cancellation and ambiguous recovery. Use fixtures for API-key launch and usage/limit classification. This phase provisions zero API keys and makes zero metered API requests. Keep Codex, remote and fix regression coverage, including recovery from existing durable workflow data.
3. **Credentialed local.** On disposable workflows, run a review with an unchanged checkout and a bounded fix with an approved edit. Verify a deliberately out-of-scope scratch candidate is rejected by Switchyard's candidate gate even if the native profile allows the edit. Resume the same transcript from a separate process. Cancel an active turn and verify process-group cleanup. Verify interrupted recovery holds without replay. Use a signed-out scratch profile for auth failure and fixtures or naturally occurring limits for expiration and quota evidence.
4. **Credentialed distributed.** Reuse the Mac mini worker, exe.dev controller and SSH forwarding. Register the Claude profile, complete an exact-head no-change review and continue on the same worker and checkout. Check terminal and checkpoint evidence and one attempt after duplicate enqueue. On a separate disposable workflow, interrupt the tunnel after session evidence. Verify cancellation, lease expiry, held session, quarantine, and retained late evidence without replay or a second result. Record live results separately from automated coverage, then return to Phase 5.6C. [Distributed smoke test](../distributed-workers.md#two-process-smoke-test)

Operator approval gates implementation. The pending native gate is the first step after approval. Leave production launch configuration in place until the checks above pass.
