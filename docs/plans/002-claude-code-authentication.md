# Claude Code authentication follow-up

- Status: Proposed for operator review before Phase 5.6C
- Date: 2026-11-24
- Baseline: Switchyard `fb0e0d0` (Phase 5.6B)

## Findings

Switchyard currently implements the API-key profile described in the [Claude provider ADR](../adr/0004-local-claude-code-provider.md). The worker factory reads `ANTHROPIC_API_KEY` on the execution host. The runtime requires it and rejects known managed-policy sources. The child gets a small environment and an explicit `apiKeyHelper`. The adapter requires `apiKeySource: "apiKeyHelper"` in the initialization frame. Anthropic excludes helper-provided keys from server-managed settings delivery, so this existing path is for an unmanaged Console key on an unmanaged host. Local execution and remote worker registration construct the same adapter. The common interface deals in sessions, turns and normalized evidence. [Claude operating guide](../claude-code.md) · [Server-managed settings](https://code.claude.com/docs/en/server-managed-settings#platform-availability)

**Native headless execution can use a stored subscription login. The launch must omit `--bare`.** The 2.1.330 binary's own help and Anthropic's headless guide both say that bare mode skips OAuth and Keychain reads. The candidate keeps `--print --restricted --safe-mode` and the explicit restrictions. A plain `--print` launch can discover repository hooks and MCP without a trust prompt, so the other flags and explicit settings are essential. [Headless execution](https://code.claude.com/docs/en/headless) · [CLI flags](https://code.claude.com/docs/en/cli-reference) · [Permissions](https://code.claude.com/docs/en/permissions)

**The Mac mini preflight rejected an endpoint policy before CLI launch.** Calling `assertClaudePolicy` with a fresh profile reproduced the error. The root-owned system file at `/Library/Application Support/ClaudeCode/managed-settings.json` contains only `sandbox.enabled: false`. The guard rejects the presence of that file regardless of its content, and changing `CLAUDE_CONFIG_DIR` leaves the machine-wide path in scope. The installed 2.1.331 CLI would fail the independent version check. Claude's sandbox setting governs shell execution, while Switchyard's Claude profile excludes shell tools and depends on file-tool permissions. That distinction permits investigation of a narrow compatibility exception, subject to approving the policy and testing the effective restrictions. [Managed settings](https://code.claude.com/docs/en/managed-settings) · [Permissions and sandboxing](https://code.claude.com/docs/en/permissions)

**A dedicated login has its own configuration, transcript and native credentials.** Anthropic documents that `CLAUDE_CONFIG_DIR` selects a distinct Keychain entry on macOS and locates the mode-0600 fallback file if Keychain writes fail, for example in a locked SSH session. Provision through `claude auth login --claudeai` as the worker's OS user with the same canonical profile path and launch environment the worker will use. Claude handles refresh and may require browser sign-in again when refresh fails or the login reaches its time limit. Verify availability in the actual worker process context after restart, including the intended login and Keychain state. Treat any credential fallback file as private profile data. [Authentication and credential management](https://code.claude.com/docs/en/authentication#credential-management)

## Proposed design

- Add `claude.authMode` with `"subscription"` and `"api-key"` in the existing agent and worker profile settings. Omission keeps the legacy API-key path. Preserve the old normalized settings and fingerprints when the effective mode is API key, including persisted fix requests and sessions. Keep its existing helper, `--bare` and optional `maxBudgetUsd`. Subscription mode requires a dedicated operator-owned private profile outside the checkout and rejects `maxBudgetUsd`.
- For subscription mode, allowlist the child environment and use only a native claude.ai login. Provision the profile through Anthropic's login flow with no other provider credentials, profiles or gateways. Require a successful same-environment `auth status --json` for the canonical profile, a supported personal paid plan and first-party `claude.ai` authentication. Check on every launch and resume. Exclude API keys, bearer and setup tokens, helpers, alternate endpoints and routing overrides, shared credential directories, and policy that can introduce a fallback. Init must still match the session, version, checkout and permissions, with no MCP or extra directories. Require the pinned subscription run's observed API-key-source value. `apiKeySource: "none"` alone proves no API key was reported and also occurs when signed out. The profile and launch environment must rule out alternate credential sources even if the login expires between status and inference. [Credential precedence and expiry](https://code.claude.com/docs/en/authentication#authentication-precedence) · [Auth status](https://code.claude.com/docs/en/cli-reference#cli-commands) · [Initialization fields](https://code.claude.com/docs/en/agent-sdk/typescript#apikeysource)
- Keep restricted and safe mode, empty setting sources, disabled custom hooks, connectors, slash commands and Chrome, strict empty MCP configuration, the narrower explicit tools, and `dontAsk` with no prompt handler. Keep protected paths and scoped edit rules. Verify tools and checkout evidence at the existing boundary. Retain the managed-source guard by default. For the Mac, evaluate an explicit, operator- and policy-owner-reviewed exception for the exact root-owned sandbox-only policy. Leave it active in the native runtime. Verify the effective sources through native diagnostics and OS policy discovery, and pin the exact reviewed setting. Validate policy stability across launch and reload before enabling execution. Refuse unknown, unreadable, changed or unverified policy, including MDM, policy helpers, managed MCP and unexpected cached or server policy. Safe mode can leave some managed customizations active and suppress others, so init alone is insufficient. Keep server policy retrieval available where applicable. Start with verified personal plans, since Team and Enterprise can receive server policy that may arrive or refresh after startup. If policy sources cannot be reliably verified or a policy requires an incompatible feature, keep the profile disabled on this Mac and use an approved compatible host or keep the existing API-key option for future authorized metered use. [Managed settings precedence](https://code.claude.com/docs/en/managed-settings) · [Server startup behavior](https://code.claude.com/docs/en/server-managed-settings#enforce-fail-closed-startup)
- Require the operator to confirm Usage credits are disabled before credentialed testing or subscription-only operation. Claude can automatically switch to paid usage credits under the same subscription login. Confirm a durable way to enforce that condition or document the operator-managed prerequisite and its limits before rollout. If strict zero-extra-spend assurance is required and the account setting cannot be verified before a usable turn, leave subscription execution disabled. Anthropic permits ordinary personal use of the unmodified native CLI and restricts offering Claude.ai login or routing subscription requests for users of a third-party product. Scope this proposal to the operator's own account and worker. Confirm applicability with Anthropic before offering a shared or customer-facing workflow. [Usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans) · [Authentication and usage policy](https://code.claude.com/docs/en/legal-and-compliance#usage-policy)
- Normalize proven login failure, subscription limit and reset time, provider throttling/overload, and API budget exhaustion in the adapter. Treat ambiguous evidence conservatively. A `429` can represent several limits. Use subscription-specific structured evidence when observed, such as a rejected `rate_limit_event` with `credits_required`. Warnings and `overageEnabled` are optional and can arrive too late to prevent billing. Preserve token telemetry and API cost estimates. Omit subscription monetary spend, since `total_cost_usd` is a client estimate. Never use these outcomes to select another credential or replay a turn. [Rate-limit events](https://code.claude.com/docs/en/agent-sdk/typescript#sdkratelimitevent) · [API errors](https://platform.claude.com/docs/en/api/errors) · [Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Keep credentials and profile paths configured on the execution host. Carry the mode and launch policy in the existing runtime/configuration identity, with no credential material in the digest. Normal refresh can retain the binding. Reprovisioning an account uses a new profile and session. Continue using exact transcript path and digest, checkout identity, operator authorization, process-group cancellation, durable claims and terminal verification. Remote dispatch keeps the existing provider/model routing and worker, checkout and runtime affinity. The controller needs no Claude authentication branch.

## Approval and validation

1. **Native gate.** Confirm the use and spending prerequisites. Test the dedicated login with 2.1.330 as the Mac worker user. Verify first-party subscription status and unchanged interactive-profile status, then run one harmless confined prompt with the candidate flags and a bare negative control. Check the initialization frame and native terminal evidence. Confirm the managed-policy decision before enabling this profile in Switchyard.
2. **Automated after approval.** Cover both modes, legacy compatibility, mode/profile changes on resume, malformed or conflicting auth/policy evidence, absent credentials, denied tools and paths, limit/error frames and missing terminal evidence. Retain fake-process tests for cancellation and recovery, and loopback tests for loss of launch response, lease fencing, late evidence and duplicate delivery. Test API-key compatibility with fixtures. Any real API-key test requires a separate approved metered run.
3. **Credentialed local after implementation.** On a disposable PR and isolated checkout, prove a native read and an authorized edit. Try an out-of-scope edit and an out-of-checkout read using harmless sentinels. Confirm denials and unchanged protected files. Resume the same transcript from a separate process and verify retained context. Cancel a running turn, verify the entire process group exits, and test an interrupted run held on restart without implicit replay. Use a fresh signed-out profile for authentication failure and fixtures for expired-login and quota events. Observe natural limits if available, without deliberately exhausting the allowance.
4. **Credentialed distributed after local pass.** Reuse the Mac mini worker, existing exe.dev controller host and verified SSH forwarding with disposable workflows. Register the Claude profile, check availability, run a read-only turn at the reconciled exact PR head and resume via the same worker and checkout. Verify the transcript, terminal frame, empty changed paths and exact head. Re-enqueue the same request and confirm one attempt. On another workflow, break the tunnel after live session evidence. Confirm worker cancellation and process cleanup, lease expiry, unknown outcome, held session and worker quarantine. Reconnect and verify late evidence cannot change the outcome or authorize a replay. Record sanitized results separately from automated coverage. [Worker operating guide](../distributed-workers.md)

The decision is whether to approve the restricted native subscription profile and the Mac's narrow policy compatibility work, or retain the existing provider behavior until both can be verified. Implementation and credentialed Switchyard validation follow that decision, before Phase 5.6C.
